dwl

This guide shows how to build and run dwl, a lightweight Wayland compositor, on Vind Linux. dwl is not part of lambda, so you compile it yourself, but the libraries it needs (wlroots and its dependencies) are installed through lambda.

1. Install the dependencies

Installing wlroots with lambda pulls in everything dwl needs to build: 

lambda reconcile

2. Build dwl

cd /source
git clone https://codeberg.org/dwl/dwl/
cd /source/dwl
export PKG_CONFIG_PATH=$PKG_CONFIG_PATH:/usr/lib64/pkgconfig
make

Some libraries install their .pc files in /usr/lib64/pkgconfig, which pkg-config does not search by default, so the export above is needed. To make it permanent, append :/usr/lib64/pkgconfig to the PKG_CONFIG_PATH line in /etc/profile.

If make fails with enum-header: not found, run it like this instead: 

make WAYLAND_SCANNER=wayland-scanner

By default dwl uses Alt as the Mod key and foot as the terminal (build it first, or change termcmd in config.h). Open a terminal with Alt+Shift+Enter and quit with Alt+Shift+Q.

3. Set up the system

Vind has no systemd-logind or elogind, so a few things that are normally automatic must be configured by hand. Run the commands in this section as root.

3.1 seatd and user groups

seatd lets your user access the screen and input devices without being root. Create a runit service at /etc/sv/seatd/run: 

#!/bin/sh
exec seatd -g seat

Then enable it and add your user (replace gumi) to the required groups: 

chmod +x /etc/sv/seatd/run
ln -sf /etc/sv/seatd /etc/service/seatd
addgroup seat        # if it does not exist yet
addgroup gumi seat
addgroup gumi video
addgroup gumi input

New groups only apply after a new login; check with id. If you see Could not connect to socket /run/seatd.sock: Permission denied, the group change has not taken effect yet.

3.2 udev

Without udevd running, dwl fails with libinput initialization failed, no input devices. udev's rules refer to a few standard system groups, and it prints a warning for each one that is missing, so create them first: 

addgroup -g 5  tty
addgroup -g 6  disk
addgroup -g 7  lp
addgroup -g 9  kmem
addgroup -g 20 dialout
addgroup -g 24 cdrom
addgroup -g 26 tape
addgroup -g 29 audio
addgroup -g 78 kvm
addgroup sgx

Then create the service at /etc/sv/udev/run: 

#!/bin/sh
(sleep 1; udevadm trigger --action=add; udevadm settle) &
exec udevd

And enable it: 

chmod +x /etc/sv/udev/run
ln -sf /etc/sv/udev /etc/service/udev

3.3 Device permissions

/dev is recreated on every boot, so the graphics device comes back accessible only to root (Failed to open DRM node '/dev/dri/card0': Permission denied). Fix it with a udev rule at /etc/udev/rules.d/70-vind-perms.rules: 

SUBSYSTEM=="drm", KERNEL=="card[0-9]*", GROUP="video", MODE="0660"
SUBSYSTEM=="input", GROUP="input", MODE="0660"

Conditions use == and assignments use =; mixing them up gives invalid KERNEL operation. Restart udev to apply the rule: 

sv restart udev

3.4 XDG_RUNTIME_DIR

Wayland needs a private runtime directory (XDG_RUNTIME_DIR must be set otherwise). Only root can write to /run/user, so the directory has to be created at boot. Add this to /etc/runit/1, after the filesystems are mounted (replace 1000 with your UID, shown by id -u): 

mkdir -p /run/user/1000 && chown 1000:1000 /run/user/1000 && chmod 700 /run/user/1000

Then point the variable at it in /etc/profile: 

if [ -z "$XDG_RUNTIME_DIR" ]; then
    export XDG_RUNTIME_DIR="/run/user/$(id -u)"
fi

The directory must be named after your UID (/run/user/1000) and owned by your user. If it is missing or owned by root, dwl exits with startup: display_add_socket_auto. Log in again after changing /etc/profile, since the variable is only set at login.

Until the boot step is in place, you can use /tmp/runtime-1000 as a replacement. Create it as your user with mkdir -m 700 /tmp/runtime-1000 and export XDG_RUNTIME_DIR=/tmp/runtime-1000 by hand.

4. Run dwl

cat > /usr/bin/start-dwl <<'EOF'
#!/bin/sh

export LIBSEAT_BACKEND=seatd
export WLR_RENDERER=pixman
export WLR_NO_HARDWARE_CURSORS=1

exec dwl
EOF

chmod +x /usr/bin/start-dwl

start-dwl

XDG_RUNTIME_DIR comes from the previous section. In a VM with stdvga there is no real graphics acceleration, and wlroots refuses software rendering by default. Setting WLR_RENDERER=pixman uses its built-in software renderer, which is the most stable choice. The alternative, WLR_RENDERER_ALLOW_SOFTWARE=1, caused garbage on screen and duplicated cursors in our tests.

For better results in QEMU, use -device virtio-vga instead of stdvga.
