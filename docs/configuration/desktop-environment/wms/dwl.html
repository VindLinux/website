dwl

This guide shows how to build and run dwl, a lightweight Wayland compositor, on Vind Linux. dwl is not part of lambda, so you compile it yourself, but the libraries it needs (wlroots and its dependencies) are installed through lambda.

1. Install the dependencies

dwl is built on wlroots. For the recommended GPU renderer (GLES2), wlroots should be built with the egl and gbm attrs. Add them to /etc/lambda/package.compattrs: 

wlroots egl gbm

Or, if you prefer to enable them for every package, add this to /etc/lambda/make.conf: 

COMP_ATTRS="egl gbm"

wlroots also depends on mesa, which needs a driver for your graphics hardware; see the mesa page. Then install everything dwl needs to build: 

lambda reconcile

To run X11 applications, see the optional XWayland page.

2. Build dwl

cd /source/dwl
export PKG_CONFIG_PATH=$PKG_CONFIG_PATH:/usr/lib64/pkgconfig
make

Some libraries install their .pc files in /usr/lib64/pkgconfig, which pkg-config does not search by default, so the export above is needed. To make it permanent, append :/usr/lib64/pkgconfig to the PKG_CONFIG_PATH line in /etc/profile.

If make fails with enum-header: not found, run it like this instead: 

make WAYLAND_SCANNER=wayland-scanner

By default dwl uses Alt as the Mod key and foot as the terminal (build it first, or change termcmd in config.h). Open a terminal with Alt+Shift+Enter and quit with Alt+Shift+Q.

3. Set up the system

Vind has no systemd-logind or elogind, so a few things that are normally automatic must be configured by hand. Run the commands in this section as root.

3.1 seatd and user groups

seatd lets your user access the screen and input devices without being root. Create a runit service at /etc/sv/seatd/run: 

#!/bin/sh
exec seatd -g seat

Then enable it and add your user (replace gumi) to the required groups: 

chmod +x /etc/sv/seatd/run
ln -sf /etc/sv/seatd /etc/service/seatd
addgroup seat        # if it does not exist yet
addgroup gumi seat
addgroup gumi video
addgroup gumi input

New groups only apply after a new login; check with id. If you see Could not connect to socket /run/seatd.sock: Permission denied, the group change has not taken effect yet.

3.2 udev

Without udevd running, dwl fails with libinput initialization failed, no input devices. udev's rules refer to a few standard system groups, and it prints a warning for each one that is missing, so create them first: 

addgroup -g 5  tty
addgroup -g 6  disk
addgroup -g 7  lp
addgroup -g 9  kmem
addgroup -g 20 dialout
addgroup -g 24 cdrom
addgroup -g 26 tape
addgroup -g 29 audio
addgroup -g 78 kvm
addgroup sgx

Then create the service at /etc/sv/udev/run: 

#!/bin/sh
(sleep 1; udevadm trigger --action=add; udevadm settle) &
exec udevd

And enable it: 

chmod +x /etc/sv/udev/run
ln -sf /etc/sv/udev /etc/service/udev

3.3 Device permissions

/dev is recreated on every boot, so the graphics device comes back accessible only to root (Failed to open DRM node '/dev/dri/card0': Permission denied). Fix it with a udev rule at /etc/udev/rules.d/70-vind-perms.rules: 

SUBSYSTEM=="drm", KERNEL=="card[0-9]*", GROUP="video", MODE="0660"
SUBSYSTEM=="input", GROUP="input", MODE="0660"

Conditions use == and assignments use =; mixing them up gives invalid KERNEL operation. Restart udev to apply the rule: 

sv restart udev

3.4 XDG_RUNTIME_DIR

Wayland needs a private runtime directory (XDG_RUNTIME_DIR must be set otherwise). Only root can write to /run/user, so the directory has to be created at boot. Add this to /etc/runit/1, after the filesystems are mounted (replace 1000 with your UID, shown by id -u): 

mkdir -p /run/user/1000 && chown 1000:1000 /run/user/1000 && chmod 700 /run/user/1000

Then point the variable at it in /etc/profile: 

if [ -z "$XDG_RUNTIME_DIR" ]; then
    export XDG_RUNTIME_DIR="/run/user/$(id -u)"
fi

The directory must be named after your UID (/run/user/1000) and owned by your user. If it is missing or owned by root, dwl exits with startup: display_add_socket_auto. Log in again after changing /etc/profile, since the variable is only set at login.

Until the boot step is in place, you can use /tmp/runtime-1000 as a replacement. Create it as your user with mkdir -m 700 /tmp/runtime-1000 and export XDG_RUNTIME_DIR=/tmp/runtime-1000 by hand.

4. Run dwl

A small launcher script saves you from exporting variables every time you boot. As root, create /usr/bin/start-dwl: 

cat > /usr/bin/start-dwl <<'EOF'
#!/bin/sh

export LIBSEAT_BACKEND=seatd
export WLR_NO_HARDWARE_CURSORS=1
# export WLR_RENDERER=pixman
export WLR_RENDERER=gles2

. "$HOME/.profile"
exec dbus-run-session -- dwl -s 'sh ~/.config/dwl/autostart.sh <&-'
EOF

chmod +x /usr/bin/start-dwl

The script does the following:

LIBSEAT_BACKEND=seatd makes wlroots use the seatd service from section 3.1. WLR_RENDERER=gles2 uses the GPU renderer (this is why wlroots needs egl and gbm, and mesa needs a driver for your GPU). WLR_NO_HARDWARE_CURSORS=1 draws the cursor in software, which avoids cursor glitches. XDG_RUNTIME_DIR comes from section 3.4.

. "$HOME/.profile" loads your own environment variables into the session. The file must exist, so create it with touch ~/.profile if you do not have one yet.

dbus-run-session starts a private D-Bus session bus and runs dwl inside it, so every program launched from the session can reach it. It is provided by the dbus package.

-s tells dwl to run a command when it starts. Here it runs the autostart script described below. dwl connects the standard input of that command to a pipe and writes status information to it; if nothing reads it, dwl freezes after a while. The <&- at the end closes that input and avoids the problem.

4.1 The autostart script

Programs that should start together with dwl go in ~/.config/dwl/autostart.sh. Create it as your normal user, not as root: 

mkdir -p ~/.config/dwl
cat > ~/.config/dwl/autostart.sh <<'EOF'
#!/bin/sh

# programs started together with dwl go here, one per line,
# each followed by & so the script does not wait for it
EOF

Every program that keeps running, such as a wallpaper setter, must be followed by &. Without it the script waits for that program to exit and never reaches the lines after it. For example, this starts the wallpaper in the background and then continues: 

swaybg -i "$HOME/Pictures/wallpaper.png" &

For example, the PipeWire page adds the audio services here. Changes to the script apply the next time you run start-dwl.

Then start dwl with: 

start-dwl

4.2 Running in a virtual machine

In a VM without graphics acceleration (such as stdvga), the gles2 renderer cannot be used, because wlroots refuses software rendering by default. In /usr/bin/start-dwl, comment out the gles2 line and uncomment the pixman line, which selects the built-in software renderer of wlroots and is the most stable choice: 

export WLR_RENDERER=pixman
# export WLR_RENDERER=gles2

The alternative, WLR_RENDERER_ALLOW_SOFTWARE=1, caused garbage on screen and duplicated cursors in our tests. For better results in QEMU, use -device virtio-vga instead of stdvga.

5. Optional: XWayland

To run X11 applications inside dwl, first enable XWayland in the system (see the XWayland page). Then, in dwl's config.mk, uncomment these two lines: 

XWAYLAND = -DXWAYLAND
XLIBS = xcb xcb-icccm

Rebuild dwl so the change takes effect: 

make clean && make

If you installed dwl system-wide, run make install again afterwards.

dwl
