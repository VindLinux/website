XWayland

XWayland is an X server that runs as a Wayland client, allowing applications designed for X11 to run alongside native Wayland applications. It provides compatibility with software that does not support Wayland natively.

On Vind Linux, XWayland requires support from both wlroots and your compositor. The configuration below uses dwl as an example, but the same principles apply to other compositors that support XWayland.

1. Build wlroots with XWayland support

XWayland support is an optional compattr in wlroots and is not enabled by default. Add xwayland to the existing wlroots entry in /etc/lambda/package.compattrs.

For example, if you are following the dwl configuration guide, your entries can look like this: 

wlroots egl gbm xwayland
xwayland glamor glx dri3 drm

The first line enables XWayland support in wlroots, while the second enables the optional glamor and glx features when building the xwayland package. These features are recommended when supported by the package configuration.

Keep any existing attributes on the corresponding lines. If an entry for either package already exists, update it instead of adding a duplicate.

Alternatively, you can configure attributes globally in /etc/lambda/make.conf using COMP_ATTRS: 

COMP_ATTRS="egl gbm xwayland glamor glx"

This setting applies globally, so package-specific configuration through package.compattrs is preferable when you only want to enable these features for the relevant packages. If you use COMP_ATTRS, preserve your existing attributes and keep them in a single assignment.

Rebuild the affected packages and reconcile the system: 

lambda reconcile

Verify the result with: 

lambda info wlroots
lambda info xwayland

The wlroots package should list xwayland among its enabled compattrs, and xwayland should be installed with the requested build features enabled.

2. Enable XWayland in your compositor

Building wlroots with XWayland support is not enough. Your compositor must also initialize and manage XWayland.

For dwl, enable the relevant XWayland configuration in config.mk and rebuild the compositor. Follow the dwl configuration guide for the exact changes.

Other compositors may enable XWayland differently. Consult the configuration instructions for your compositor if it does not use the same build options as dwl.

3. Test XWayland

Install xeyes, available in the Vind Linux package repository, and run it from a terminal inside your Wayland session: 

xeyes

If a window containing two eyes appears and follows your cursor, XWayland is working.

If the application reports Can't open display, verify that wlroots was rebuilt with the xwayland compattr and that your compositor was built and configured to start XWayland. Also make sure you are launching the application from the active graphical session.
