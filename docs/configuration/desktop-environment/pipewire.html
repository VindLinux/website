PipeWire

PipeWire is a low-latency multimedia server that handles audio and video streams. It provides compatibility layers for ALSA, PulseAudio and JACK, so most applications work without changes. This guide covers a basic desktop audio setup: speakers and wired headphones (3.5 mm or USB). It assumes you already followed the dwl guide, which sets up udev, seatd and XDG_RUNTIME_DIR.

A working setup needs three programs running as your normal user: pipewire (the server), wireplumber (the session manager, which decides where sound goes and switches outputs when you plug in headphones) and pipewire-pulse (the PulseAudio compatibility layer used by browsers, Discord, Steam and others).

1. Enable the compattrs

The optional features of pipewire are compattrs, and none is enabled by default. For basic audio you need four of them:

alsa talks to the sound drivers of the kernel; without it no sound is produced. udev detects devices when you plug or unplug them. pulse enables the PulseAudio compatibility layer. sndfile enables utilities such as pw-play, which are useful for testing.

Add them to /etc/lambda/package.compattrs: 

pipewire alsa udev pulse sndfile

Or, to enable them for every package, add this to /etc/lambda/make.conf: 

COMP_ATTRS="alsa udev pulse sndfile"

Keep any existing attributes, and if an entry for pipewire already exists, update it instead of adding a duplicate. Everything else (Bluetooth, codecs, JACK, cameras, and so on) is optional and can stay disabled for this setup.

2. Install PipeWire and WirePlumber

lambda install pipewire wireplumber

To confirm, run lambda info pipewire and check that the four compattrs appear under the enabled compattrs. WirePlumber is required: without a session manager, PipeWire starts but does not connect anything.

3. Add your user to the audio group

The device nodes in /dev/snd belong to the audio group. If your user is not a member, PipeWire cannot open the sound card and falls back to a useless Dummy Output. The group is created in section 3.2 of the dwl guide; if it does not exist yet, create it with addgroup -g 29 audio. Then, as root (replace gumi with your user): 

addgroup gumi audio

New groups only apply after a new login. Log out and log back in, then check: 

id

audio must appear in the list. Do not rely on groups user: with a user name it reads the system group file and does not show the groups of your current session.

The sound card must also be visible to udev, so udevd has to be running as described in the dwl guide.

4. Start the services

PipeWire, WirePlumber and pipewire-pulse run as your normal user, never as root, so they are not runit services. The order matters: the PulseAudio layer needs the server to be running already, otherwise it fails with can't connect: Host is down. To try them by hand inside your session: 

pipewire &
sleep 1
wireplumber &
sleep 1
pipewire-pulse &

To start them automatically, add the same commands to ~/.config/dwl/autostart.sh, the script that start-dwl runs when dwl starts (see the dwl guide): 

#!/bin/sh

pipewire &
sleep 1
wireplumber &
sleep 1
pipewire-pulse &

Each command must end with &. Without it the script waits for that program to exit, and every line after it (including the other audio services) never runs. This also applies to any other program you keep in the same script, such as a wallpaper setter, which has to come with & as well. The services start with the session and also have access to the D-Bus session bus created by start-dwl. XDG_RUNTIME_DIR must be set (the dwl guide does this in /etc/profile), because PipeWire creates its sockets in it, including the PulseAudio one at $XDG_RUNTIME_DIR/pulse/native.

If you need to restart everything, stop the old processes first so a stale instance does not keep running: 

pkill wireplumber; pkill pipewire-pulse; pkill pipewire

5. Verify

wpctl status

Under Audio you should see your sound card in Devices and real outputs in Sinks, with * marking the default. If only Dummy Output is listed, PipeWire cannot see your card: check the audio group (section 3) and that udevd is running.

Then confirm that the PulseAudio layer answers: 

pactl info

The output should contain Server Name: PulseAudio (on PipeWire ...). Finally, play a test file through PipeWire: 

pw-play file.wav

Volume and mute can be adjusted with: 

wpctl get-volume @DEFAULT_AUDIO_SINK@
wpctl set-mute @DEFAULT_AUDIO_SINK@ 0
wpctl set-volume @DEFAULT_AUDIO_SINK@ 70%

6. Unmute the sound card

Many sound cards start muted at the ALSA mixer level, which wpctl cannot change. If the volume looks fine but nothing is audible, install alsa-utils with the alsamixer compattr, which is disabled by default. Add it to /etc/lambda/package.compattrs: 

alsa-utils alsamixer

Then run lambda install alsa-utils. Without the compattr the package installs, but alsamixer is not built.

Run alsamixer, press F6 to select your card, and press M on any channel marked MM (such as Master, Headphone or Speaker) to unmute it. The same can be done without the interface: 

amixer -c 0 scontrols
amixer -c 0 sset Master unmute

While PipeWire is running it holds the sound card, so aplay fails with Resource busy. This is expected. Use pw-play or paplay to test sound instead.

7. Headphones and speakers

WirePlumber switches the output when you plug or unplug wired headphones. On many laptops, speakers and headphones are a single sink (for example Line Output) whose port changes automatically, so the default sink in wpctl status may not move even though the sound does. Play something and plug the headphones in to test it.

8. Browsers and other applications

Browsers detect the audio server only when they start. After starting or restarting pipewire-pulse, close the browser completely and open it again. While something is playing, this command should list the application: 

pactl list sink-inputs short

If the application is not listed, check that XDG_RUNTIME_DIR is set in the shell that launched it and that $XDG_RUNTIME_DIR/pulse/native exists. If it is listed but still silent, check the volume and mute state of the default sink and of the tab or application itself.

9. Messages you can ignore

These messages appear in the logs of a working setup.

RTKit error: org.freedesktop.DBus.Error.ServiceUnknown means that the RTKit service, which grants realtime priority to audio threads, is not running. Audio works without it.

support.logind ... failed to load only affects seat monitoring for Bluetooth, and Vind has no logind anyway.

Messages saying that the BlueZ, V4L2 or libcamera plugins are missing or broken are expected, because those compattrs are not enabled.

10. Troubleshooting

Only Dummy Output in wpctl status: your session does not have the audio group yet (log in again and check id), udevd is not running, or PipeWire was built without alsa and udev.

No audio processes after logging in and Could not connect to PipeWire in wpctl status: the autostart.sh script is stuck on a command without & that comes before the PipeWire lines. Add & to it (section 4).

can't connect: Host is down in pipewire-pulse: it was started before pipewire. Keep the order from section 4.

Sound card visible but silent: the card is muted in the ALSA mixer. See section 6.

aplay reports Resource busy: PipeWire is holding the card. Use pw-play.

alsamixer: not found: alsa-utils was installed without the alsamixer compattr.

Sound works with pw-play but not in the browser: restart the browser after pipewire-pulse is running and check XDG_RUNTIME_DIR (section 8).
