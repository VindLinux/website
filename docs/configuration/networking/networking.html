Networking on the Final System

This guide shows how to get Wi-Fi working on an installed Vind Linux system, and how to make it come up by itself at every boot. Wi-Fi on Vind needs three pieces running under runit: the system dbus-daemon, iwd (which handles the link and authentication) and dhcpcd (which gets the IP address). Run every command as root, in the order shown.

It assumes you finished the x86_64 Handbook: the packages from chapter 6 (iwd, dbus, dhcpcd, linux-firmware), runit from chapter 11, and the dhcpcd service created there. On a wired connection you only need the dhcpcd service, so this guide is not required.

1. Prepare the directories and links

Clients look for the system bus socket in /var/run/dbus, while the daemon creates it in /run/dbus. Link one to the other: 

mkdir -p /run/dbus /var/run
[ /var/run -ef /run ] || ln -sfn /run/dbus /var/run/dbus

/run is a tmpfs and is empty on every boot, so the /run/dbus directory is recreated by the service in section 3. The link itself lives on disk and only has to be made once. The second line is skipped when /var/run is already a link to /run, where the link would be pointless.

2. Prepare D-Bus

The system bus drops privileges to a messagebus user and needs a machine ID. Create them only if they are missing: 

id messagebus >/dev/null 2>&1 || {
    groupadd -r messagebus
    useradd -r -g messagebus -d /run/dbus -s /sbin/nologin -c 'D-Bus' messagebus
}
dbus-uuidgen --ensure

Then install the D-Bus policy that lets iwd own its name on the bus. The iwd package puts the file in a nested path that D-Bus does not read, so copy it to the right place: 

mkdir -p /usr/share/dbus-1/system.d
cp /usr/share/dbus-1/dbus-1/system.d/iwd-dbus.conf /usr/share/dbus-1/system.d/

3. The D-Bus service

mkdir -p /etc/sv/dbus/log/main

cat > /etc/sv/dbus/run <<'EOF'
#!/bin/sh
exec 2>&1
mkdir -p /run/dbus
exec dbus-daemon --system --nofork --nopidfile
EOF
chmod +x /etc/sv/dbus/run

cat > /etc/sv/dbus/log/run <<'EOF'
#!/bin/sh
exec svlogd -tt ./main
EOF
chmod +x /etc/sv/dbus/log/run

ln -sf /etc/sv/dbus /etc/service/dbus

--nofork is required for the same reason as in the dhcpcd service: runsv respawns anything that exits, so a daemon that forks into the background looks like a crash. The log/run script is not optional once the log/ directory exists.

If you started dbus-daemon by hand earlier, stop it first, or the service cannot bind the socket. runit starts new services within a few seconds. Then test the bus: 

sv status dbus
dbus-send --system --print-reply --dest=org.freedesktop.DBus /org/freedesktop/DBus org.freedesktop.DBus.GetId

The second command must print a UUID. If you edit the policy files later, make the daemon reread them with sv hup dbus instead of starting another instance.

4. The iwd service

mkdir -p /etc/sv/iwd/log/main

cat > /etc/sv/iwd/run <<'EOF'
#!/bin/sh
exec 2>&1
[ -S /run/dbus/system_bus_socket ] || { sleep 2; exit 1; }
exec /usr/libexec/iwd
EOF
chmod +x /etc/sv/iwd/run

cat > /etc/sv/iwd/log/run <<'EOF'
#!/bin/sh
exec svlogd -tt ./main
EOF
chmod +x /etc/sv/iwd/log/run

ln -sf /etc/sv/iwd /etc/service/iwd

runit has no dependencies between services, so the run script waits for the D-Bus socket itself: if it is not there yet, the script sleeps and exits, and runsv tries again. This is what keeps the boot order correct. 

sv status dbus iwd dhcpcd

All three must say run.

5. Connect to the network

iwctl

Inside the client (replace wlan0 with the name shown by device list): 

device list
station wlan0 scan
station wlan0 get-networks
station wlan0 connect "WIFI_NAME"

iwctl asks for the passphrase and iwd saves the network in /var/lib/iwd. From then on it reconnects by itself every time the service starts, so you only do this once.

6. Get an IP address and test

The dhcpcd service from the handbook watches all interfaces and asks for an address as soon as the link comes up, so nothing else is needed: 

ip addr show wlan0
ping -c 3 1.1.1.1

If the interface has no address and you have not created the dhcpcd service, ask for one by hand instead: 

udhcpc -i wlan0

Do not run it together with the dhcpcd service, since both would fight over the interface.

7. Check it after a reboot

reboot

After logging in, without running anything by hand: 

sv status dbus iwd dhcpcd
iwctl station wlan0 show
ping -c 3 1.1.1.1

The station must be connected to your network and the ping must answer.

8. Troubleshooting

iwctl cannot connect, or shows no devices even though the card exists: check the services and the socket, then read the logs. 

sv status dbus iwd
ls -l /run/dbus/system_bus_socket
tail -n 30 /etc/sv/dbus/log/main/current
tail -n 30 /etc/sv/iwd/log/main/current

iwd keeps restarting: it is waiting for a D-Bus socket that does not exist. Fix the dbus service first.

An AccessDenied error, or a message that net.connman.iwd cannot be owned: the policy file from section 2 is missing. Copy it, then reload: 

sv hup dbus
sv restart iwd

iwctl device list is empty: there is no wireless interface. Check that ip link shows it, that linux-firmware is installed, and look for firmware errors in dmesg. 

ip link
dmesg | grep -i firmware

Connected, but no address: check sv status dhcpcd and its log in /etc/sv/dhcpcd/log/main/current.

Name resolution fails while pinging an IP works: see /etc/resolv.conf in the handbook's Networking chapter.
