Flatpak

This guide shows how to install Flatpak on Vind Linux and use it to run applications that are not packaged for lambda. Flatpak itself is installed through lambda; the applications are downloaded already compiled from Flathub, so nothing has to be built from source. Run the commands that change the system as root, and the Flatpak commands as your normal user.

It assumes a working dwl session, since graphical applications need a Wayland compositor.

1. Install Flatpak

lambda sync
lambda mutate append flatpak
lambda reconcile

lambda also installs everything Flatpak needs, such as bubblewrap, xdg-dbus-proxy, ostree and appstream. By default the system-helper attribute is off, so Flatpak is built without polkit and applications are installed per user, with --user, as shown below.

Check that it works: 

flatpak --version

2. Check the kernel

Flatpak isolates each application with bubblewrap, which needs user namespaces. Run these as your normal user: 

unshare --user --pid echo ok
cat /proc/sys/user/max_user_namespaces
ls -l /dev/fuse

The first command must print ok, the second must be greater than 0, and /dev/fuse must exist. If the second one is 0, enable it as root with: 

echo 15000 > /proc/sys/user/max_user_namespaces

3. D-Bus session

Flatpak uses a D-Bus session bus for communication with desktop services and portals such as file choosers, links and notifications. Vind does not use systemd-logind, so the session bus is provided by a dedicated runit service.

Create the service as root (replace gumi with your user in the script and in the checks below): 

mkdir -p /etc/sv/dbus-session/log
mkdir -p /var/log/dbus-session

cat > /etc/sv/dbus-session/run <<'EOF'
#!/bin/sh
exec 2>&1

USER_NAME=gumi
USER_ID=$(id -u "$USER_NAME")
RUNTIME="/run/user/$USER_ID"

[ -d "$RUNTIME" ] || { sleep 2; exit 1; }
rm -f "$RUNTIME/bus"

exec chpst -u "$USER_NAME" env \
    HOME="/home/$USER_NAME" \
    USER="$USER_NAME" \
    XDG_RUNTIME_DIR="$RUNTIME" \
    XDG_DATA_DIRS="/home/$USER_NAME/.local/share/flatpak/exports/share:/var/lib/flatpak/exports/share:/usr/local/share:/usr/share" \
    DBUS_SESSION_BUS_ADDRESS="unix:path=$RUNTIME/bus" \
    dbus-daemon \
        --session \
        --nofork \
        --nopidfile \
        --address="unix:path=$RUNTIME/bus"
EOF

cat > /etc/sv/dbus-session/log/run <<'EOF'
#!/bin/sh
exec svlogd /var/log/dbus-session
EOF

chmod +x /etc/sv/dbus-session/run
chmod +x /etc/sv/dbus-session/log/run

ln -sf /etc/sv/dbus-session /etc/service/dbus-session

The service runs dbus-daemon as the normal user instead of root and creates the session bus at /run/user/<uid>/bus. An old socket is removed before starting the daemon so that the service can recover after an unclean shutdown.

The service requires chpst, which is provided by runit. The user's runtime directory must also exist before the service can start. The dwl guide creates /run/user/1000 during boot.

The service has a dedicated runit logger, so D-Bus output does not get written directly to the terminal: 

sv status dbus-session

To inspect the service log: 

tail -f /var/log/dbus-session/current

Check that the session bus socket exists: 

ls -l /run/user/$(id -u gumi)/bus

Then check that the bus responds: 

su - gumi -c 'DBUS_SESSION_BUS_ADDRESS="unix:path=/run/user/$(id -u gumi)/bus" dbus-send --session --dest=org.freedesktop.DBus --type=method_call --print-reply /org/freedesktop/DBus org.freedesktop.DBus.ListNames'

Set the session bus address in /etc/profile, below the block that sets XDG_RUNTIME_DIR: 

if [ -z "$DBUS_SESSION_BUS_ADDRESS" ]; then
    export DBUS_SESSION_BUS_ADDRESS="unix:path=$XDG_RUNTIME_DIR/bus"
fi

Log in again after changing /etc/profile. Programs started from the session will then use the same D-Bus bus.

The /usr/bin/start-dwl script does not need dbus-run-session. Its final command can simply be: 

exec dwl

4. XDG_DATA_DIRS

Flatpak exports desktop files, icons and other application data into XDG data directories. Add the Flatpak export directories to XDG_DATA_DIRS in /etc/profile or ~/.profile: 

export XDG_DATA_DIRS="$HOME/.local/share/flatpak/exports/share:/var/lib/flatpak/exports/share:/usr/local/share:/usr/share"

Log in again after changing the file.

5. Add Flathub and install an application

Add the Flathub repository for your user: 

flatpak --user remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo

Then install an application by its ID, which you can find with flatpak search or on flathub.org. Flatpak also downloads the runtime the application needs (org.freedesktop.Platform), which takes between 1 and 2 GB, so check the free space in your home first: 

df -h /home
flatpak --user search <name>
flatpak --user install flathub <application-id>

Flatpak asks to confirm the runtime and then the application. Add -y to answer yes to all questions. For a complete example, see the Firefox guide.

6. Run it

Inside the dwl session (opened with start-dwl), open a terminal with Alt+Shift+Enter and run: 

flatpak run <application-id>

The application uses the D-Bus session created by the dbus-session runit service.

In a VM without graphics acceleration, applications use software rendering and are slow, but they work. On real hardware they run normally.

To list or remove what you installed: 

flatpak --user list
flatpak --user uninstall <application-id>
flatpak --user uninstall --unused

7. Troubleshooting

Cannot autolaunch D-Bus without X11 $DISPLAY or another error connecting to the session bus: check that the dbus-session service is running and that DBUS_SESSION_BUS_ADDRESS points to the user's bus. 

sv status dbus-session
echo "$DBUS_SESSION_BUS_ADDRESS"
ls -l "$XDG_RUNTIME_DIR/bus"

If the service keeps restarting, make sure the runtime directory exists: 

ls -ld /run/user/$(id -u)

If the service is running but the bus does not respond, check its log: 

tail -n 50 /var/log/dbus-session/current

bwrap: No permissions to create new namespace: user namespaces are disabled. Redo the checks in section 2.

Do you want to install it? [Y/n] waiting: it is just asking for confirmation. Press Enter, or use -y.

The application does not appear in a launcher: Vind has no desktop environment, so run it from the terminal with flatpak run.
